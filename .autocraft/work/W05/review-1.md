## Findings
- [MAJOR] Reconfirm editor TOCTOU (`onboarding-reconfirm.ts`, "Review additions" dialog). The summary text is captured when the dialog opens, but `save.onclick` sends the live `items` array. The dialog is non-modal (`aria-modal` is only an attribute) and the entry chips and list stay clickable and tabbable underneath. The user can add or change chips after reading the summary and then press "Yes, save this", saving things they were not shown. If an item becomes unresolved, `toApiItems` throws inside the async handler and nothing visible happens. Fix: snapshot `items` (and the wire items) when the dialog opens and send exactly that, or make the entry inert (`inert` attribute) while the dialog is open; wrap `toApiItems` in try/catch with a visible message. Add a test (open the dialog, add a chip behind it, assert the saved rules equal the summary).
- [MAJOR] Typed-but-not-added text is silently dropped on "No, nobody" (`onboarding.ts` S-02, `nobody.onclick`). With an empty list, "No, nobody" is enabled. If the user types "peanuts" and taps "No, nobody" (instead of Add), `confirmedNone` is recorded and the typed allergy is lost with no warning. This conflicts with the spirit of AC-2.4 (nothing silently dropped) and is the exact failure the gate exists to prevent. Fix: disable "No, nobody" (with the hint text) while `#avoid-text` is non-empty, or auto-parse the pending text on Continue/No. Same for Continue (pending text is not in the review list). Add a test.
- [MINOR] Gate is a blacklist. Any `gate.status` other than `noHousehold` / `refused+safetyUnanswered` opens the shell, and a missing `gate` throws a TypeError (stale DOM on later renders). Prefer a whitelist: shell only for `open` and `refused/reconfirmationDue`, anything else draws the fatal page. No test covers `household.get` failure or an unreadable snapshot (`restore()` returns "unreadable", the core is then empty, onboarding starts at S-01, and the next save silently overwrites the unreadable snapshot). Safety-wise this re-asks, which fails safe, but add a test and consider telling the user.
- [MINOR] Double-tap hazard: a fast double-click on "Continue" can land the second click on whatever the next screen puts under the pointer ("Yes, save this"). Suggest ignoring clicks for about 400 ms after S-02b is drawn, or checking `event.detail`.
- [MINOR] Reconfirm `safety.addRule` loop saves items one by one; on a mid-way failure the earlier rules are saved and the list is not reset, so a retry duplicates. Refresh after partial failure.
- [NIT] `confirmRemove` sets `no.textContent` twice; the reconfirm remove dialog has no focus handling for Tab leaving it.
