[MAJOR] Release `strings` check can false-pass (apple-macos.yml release-hygiene). Swift stores UTF-8 literals of <=15 bytes as immediates in machine code, not in __cstring. "-OMPUITestSeed" (14 B) and "-OMPUITestInbox" (15 B) are small strings, so `strings` will probably not see them; only "-OMPUITestSpeech" (16 B) is reliably found. The ">100 lines" guard proves nothing about this. Fix: add a self-check (build a tiny Swift/C binary or file with a 16+ byte `OMPUITest...` literal and assert the same grep finds it), AND add a check that does not depend on literal layout: e.g. `nm`/`strings` for the hook type names (`UITestInbox`, `UITestSeed`, `UITestSpeech`-style symbols in CompositionRoot.swift:138-333; Release keeps type metadata names unless stripped) or build Release with `-Xfrontend -disable-...` is not needed. Also make the match case-insensitive on "UITest".
