## Medium

**M1. Allergy/household data and inbox are included in device backups; "Delete all data" cannot reach backups.**
`Packages/Apple/Sources/OMPData/Store/PersistenceStore.swift:19-23` (Application Support/OffMyPlate), inbox in the App Group container (`ShareInboxWriter.swift:14-19`). Neither sets `isExcludedFromBackup`. Plan s.11 and the privacy copy say data "stays on the device". Fix: set `URLResourceValues.isExcludedFromBackup = true` on the store directory and the Inbox directory (re-apply after recreation in `DirectoryShareInboxWriter.write`), or state the backup behaviour explicitly in the privacy copy and in plan s.11. Decide as owner.

**M2. Release build has no automated proof that the DEBUG hooks are absent.**
`App/OffMyPlate/CompositionRoot.swift:19-35, 137-306, 308-333` are correctly inside `#if DEBUG`, and the three arguments (`-OMPUITestSeed/-Inbox/-Speech`) appear nowhere else in non-test code. But CI only builds Debug for the simulator, so a future stray reference would not be caught. Fix: add a Release build job (CODE_SIGNING_ALLOWED=NO) that runs `strings`/`nm` on the binary and fails if `OMPUITest` is present; or a grep lint that every `OMPUITest` occurrence sits within a `#if DEBUG` region.

**M3. Safety lint for `UserConfirmation(` is name- and text-based; its allowed-set is wider than the policy.**
`scripts/lint-safety.sh:25, 156` allows any `Packages/Apple/Sources/OMPFeatures/**/Approval*.swift`, but policy (ApprovalWeekBar.swift:5-7, plan s.11) is exactly two files. `UserConfirmation.init` is `public` (`Packages/Core/Sources/OMPDomain/Plan/PlanLifecycle.swift:10`), so any module can build one; a new `ApprovalFoo.swift`, `typealias UC = UserConfirmation; UC()`, or `UserConfirmation .init` style variants evade the grep. Currently the invariant holds (see Passed). Fix: allow-list the two exact paths (`Plan/ApprovalSheet.swift`, `Plan/ApprovalWeekBar.swift`); also ban `typealias .* = UserConfirmation`; add a CODEOWNERS entry for these two files and `scripts/lint-safety.sh`.

## Low

**L1. Inbox quantity can overflow to infinity after merge.** `Packages/Core/Sources/OMPServices/ImportService.swift:141-143, 184-186` sums `Quantity` values; decode only checks each is finite (`InboxImport.swift:58`). A file with 1e308 twice yields +inf persisted into the store. Not reachable by a remote attacker (same-team sandbox only) but a corrupt-data path. Fix: cap `quantity` at decode (for example <= 100_000) and reject non-finite sums in `Quantity.adding`.

**L2. Inbox folder has no file-count cap and `failed/` grows without bound.** `DirectoryInboxStorage.fileNames()` (`InboxStorage.swift:85-89`) and `quarantine` (`:111-120`). Per-file cap (256 KB, checked before and after read) is good. Fix: limit drained files per run (for example 200) and prune `failed/` by age/count; report in `ImportSummary`.

**L3. Inbox read follows symlinks and has a size TOCTOU.** `InboxStorage.swift:91-109` uses `fileExists`/`attributesOfItem` (follows links) then `Data(contentsOf:)`. Only same-App-Group code (the team's own extension) can write there, so exploitability is very low. Fix: use `FileHandle.read(upToCount: maxFileBytes+1)` instead of stat-then-read; skip entries whose `FileAttributeKey.type` is symbolic link.

**L4. `failed/` directory and Inbox directory are created without an explicit protection attribute in the app side.** `InboxStorage.swift:116` (`createDirectory` with no attributes). The entitlement default (`NSFileProtectionComplete`, both `.entitlements`) covers new files, so this is defense in depth only. Fix: pass `[.protectionKey: .complete]` on iOS, as the writer already does.

**L5. Supply-chain hygiene in CI.** `.github/workflows/*.yml` and `.github/actions/apple-setup/action.yml`: permissions are `contents: read`, no `pull_request_target`, no secrets, checkout pinned by SHA (good). Gaps: the pinned SHA `11d5960a326750d5838078e36cf38b85af677262` is commented "v4.4.0"; verify it against the upstream tag before release (could not verify offline); `brew install xcodegen` is unpinned and a version mismatch only warns (`action.yml`, vs `App/.xcodegen-version`) - make it a failure or install a pinned release; no `.github/dependabot.yml` (add `github-actions` ecosystem), no CodeQL/secret-scanning workflow (the repo is public: enable GitHub secret scanning + push protection in repo settings).

**L6. `StoreErase` secure-delete caveats.** `Packages/Apple/Sources/OMPData/Store/StoreErase.swift:31-64`. No SQL injection possible (all statements are constant literals, no interpolation). Handles are closed (`defer sqlite3_close`) and the prepared statement is finalised before close. Remaining: `Thread.sleep` (`:44`) blocks a thread for up to ~0.8 s; it runs off the main actor today, keep it so (add a test or `@concurrent` annotation). `secure_delete` and VACUUM cannot guarantee flash-level erasure; Data Protection Complete plus device encryption is the real control, say so in the privacy copy. Backups (M1) are outside this.

**L7. Placeholder App Group / bundle prefix.** `App/Config/Base.xcconfig:7-10` (`group.app.offmyplate`, `app.offmyplate`) is a shared default; a clash would only break signing, not security, but the release owner must set real values in git-ignored `Local.xcconfig`. The extension degrades safely (writes fail with C-173) if the group is unavailable (`ShareViewController.swift:55-60`).

## Passed / no finding
- **Secrets:** no keys, tokens, `.p12`, `.mobileprovision`, `.p8`, `.pem`, `.env` in the tree or in history (regex scan of all revisions for AWS/GitHub/Slack/OpenAI/PEM patterns: none). `Local.xcconfig` is git-ignored; only `.example` (placeholder team `ABCDE12345`) and `Base.xcconfig` (empty team) are committed. Authors in history: two noreply/personal GitHub addresses and the Claude noreply; not secrets, but note author emails are public.
- **SCA:** zero third-party packages (Core and Apple `Package.swift` use only local `.package(path:)`; `App/project.yml` only local paths); no `Package.resolved` exists, none needed. `lint-no-network.sh` and `lint-core-imports.sh` enforce this. Swift toolchain on Linux is gpg-verified in `bootstrap-swift-linux.sh`.
- **Inbox parsing:** file name must match `InboxFiles.importID` (a-z0-9-, 1-64 chars) so no path traversal; id inside the JSON must equal the file name; schemaVersion first; item/line caps (500), name cap 200, finite/positive quantity, 256 KB cap; bad files go to `failed/`, storage errors keep the file for retry; idempotent via processed-id store.
- **Parsers:** all inputs capped before work (`ShoppingTextParser` 64 KB / 500 lines, `SafetyTextParser.maxInputLength`, `SpokenCommandParser.maxTranscriptLength`, resolver `maxQueryLength`); no `NSRegularExpression`/regex literals in `OMPDomain/Parsing`, so no regex DoS.
- **Share Extension:** activation rule is text only; links Domain/Recipes/UI/OMPShare only (never Services/Data); loader reads at most cap+1 bytes; writes one atomic file with `.completeFileProtection`.
- **Entitlements/Info.plist/privacy:** App Group + `NSFileProtectionComplete` on both targets; microphone and speech usage strings present and honest; `requiresOnDeviceRecognition = true` and unsupported devices refuse (`SystemSpeechBackend.swift:60-66`); `ITSAppUsesNonExemptEncryption=false`; privacy manifests declare no tracking/collection and no required-reason APIs - I found no `UserDefaults`, file-timestamp, disk-space or boot-time use (only `.size` from `attributesOfItem`, not a timestamp). Re-check if any such API is added.
- **Logging:** `OMPLog.errorKind` logs the type name only; every `privacy: .public` interpolation is an error type name, a constant, or (DEBUG only) the seed name. No PII logged, no `print` in app code (only in the `seed-review-sheet` CLI).
- **Safety invariants:** `UserConfirmation(` in non-test source only at `Plan/ApprovalSheet.swift:129` and `Plan/ApprovalWeekBar.swift:16` (other hits are tests or lint fixtures). `SafetyClearance.init` is `fileprivate` (`SafetyGate.swift:28`), constructed only at `SafetyGate.swift:101`; the compiler enforces this across modules. `OMPSafetyCheck` imports only Foundation and OMPDomain and depends only on `OMPDomain` in `Package.swift:24`; no Planner/Services reference.
