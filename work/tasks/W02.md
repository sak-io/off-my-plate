## Brief

- **Goal:** `OMPRecipes` can load the seed without `Bundle.module` when built for Wasm: a generator turns `Resources/seed/*.json` into Swift source; a CI check fails if the generated file differs from the JSON; the native build keeps using the bundle (or the same embedded source, if equal in behaviour).
- **Depends on:** W01. **ACs:** ADR 0010 unchanged; sign-off sheet still current.
- **Tests:** loader on embedded data equals loader on bundle data; drift check proven to fail on a planted change.

## Findings from W01 that this task MUST address (spike report: docs/windows/w01-spike-report.md)
- **Hard requirement:** root-cause and fix the 4 process aborts (exit 134) that are NOT file-system related: `OnboardingFlowTests/addedMemberBlocksPlanning`, `OnboardingFlowTests/endToEnd`, `PlanServiceTests/editApprovedCreatesRevision`, `SafetyRecheckTests/ruleAddedAfterApproval`, plus the `JSONEncoder.OutputFormatting` "failed to demangle witness" crash in `DataServiceTests/deleteAllLeavesNothing`. They sit in the plan-edit and rule-recheck (R1) flows the web app depends on. No web UI work (W04+) starts until these pass on Wasm or are proven harmless.
- Seed content arrives as bytes from the host through `SeedLoader.load(SeedFiles)`; keep the bundle path for native; the one `#if !os(WASI)` shim in `SeedLoader.bundledURL` stays unless made unnecessary.
- The file-system inbox and stores (`DirectoryInboxStorage`) stay behind their protocols; the Wasm test set uses in-memory implementations; document which tests are excluded on Wasm and why.
- Add the byte-identical golden: the same seeded household yields the same week plan (JSON) natively and on Wasm.
- Time zone, locale and "now" are explicit inputs (Wasm defaults: GMT, en_001). Audit `Int` arithmetic, hashing and millisecond-date maths for 32-bit `Int` on wasm32.
- Run the safety suite on Wasm in a release build as its own CI step (debug takes ~2.5 min); pin the Wasm SDK checksum (6.2.4: 32fdb8772d73bb174f77b5c59bc88a0d55003d75712832129394d3465158fb43) and keep the compiler image and SDK in lock step.
