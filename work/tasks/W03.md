## Brief

- **Goal:** a new `OMPWeb` target exporting a small set of functions (JSON in, JSON out) over `OMPServices`: household and safety answers, plan generate/edit/regenerate, approval, pantry, shopping, import, learning, delete-all, state export/import for storage. In-memory repositories with snapshot import and export. No third-party dependencies. `UserConfirmation` is created only in ONE file (`ApprovalBridge.swift`) called only by an explicit confirm message; `lint-safety.sh` allow-list and CODEOWNERS are updated for that exact file in this task, with fixtures.
- **Depends on:** W01, W02. **ACs:** AC-5.x (explicit approval), AC-1.x/AC-2.x (mandatory safety), AC-16.x (delete all).
- **Tests:** facade-level tests that mirror the service tests; gate cannot be bypassed through any export; a non-confirm message never approves.

## Findings from W01 for this task
- Single Wasm module with a small byte-oriented API (JSON in, JSON out); `@_expose(wasm, "name")` with `@_cdecl`, or a WASI reactor (`-Xclang-linker -mexec-model=reactor`, `_initialize`); synchronous exports (there are no threads; actors and `Task.sleep` work on a single-thread executor).
- Every call carries time zone, locale and "now" from JS; never read host defaults (GMT/en_001 on Wasm).
- Measure the production `.wasm` size (release, `-Osize`, strip) and report it; the debug test wasm was 102 MB.
- Not yet measured: behaviour in a browser or Node runtime; prove the module loads and one plan generates in a headless browser as part of W04's first test.
- **Link flags (from W02, mandatory):** link the Wasm module (and any Wasm test product) with `-Xlinker -z -Xlinker stack-size=4194304 -Xlinker --stack-first -Xlinker --global-base=4194304`. The default shadow stack is too small for debug builds and an overflow silently corrupts heap and data (docs/windows/w02-report.md, section 1). Seed content comes from `SeedLoader.embeddedFiles()` or host bytes via `SeedLoader.load(SeedFiles)`; never `Bundle`.
